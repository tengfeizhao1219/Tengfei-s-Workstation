# 用户测试脚本 - 标准化测试流程

## 🎯 测试概述

### 测试目的
通过观察真实用户使用产品，发现可用性问题，收集改进建议，验证设计假设。

### 测试类型
- **概念测试**: 验证核心概念和流程
- **可用性测试**: 发现使用中的问题
- **对比测试**: 比较不同设计方案
- **接受度测试**: 评估用户接受程度

### 测试规模
- **小型测试**: 3-5名用户 (发现80%问题)
- **中型测试**: 5-8名用户 (发现90%问题)
- **大型测试**: 8-12名用户 (发现95%问题)

## 📋 测试流程

### 阶段1: 欢迎和介绍 (5分钟)
#### 开场白
"你好，感谢你参加今天的用户测试。我是[你的名字]，今天将引导你完成测试。"

#### 测试说明
1. **测试目的**: "我们正在测试一个新的产品设计，需要你的真实反馈来帮助我们改进。"
2. **测试内容**: "你会完成几个任务，并分享你的想法和感受。"
3. **重要说明**: 
   - "我们测试的是设计，不是你的能力"
   - "任何问题都是设计的问題，不是你的问题"
   - "请大声说出你的想法"
   - "测试过程会被录制，仅用于改进产品"

#### 签署同意书
"请阅读并签署这份测试同意书。"

### 阶段2: 背景了解 (5分钟)
#### 问题列表
1. "请简单介绍一下你自己。"
2. "你平时使用类似产品吗？频率如何？"
3. "你通常用什么设备使用这类产品？"
4. "你对这类产品有什么期望或需求？"

### 阶段3: 任务测试 (20-30分钟)
#### 任务指导
"现在我会给你一些任务卡片，请按照卡片上的说明完成任务。请记住：大声说出你的想法。"

#### 标准任务集 (电商示例)
**任务1: 浏览和发现**
"假设你想买一个无线耳机，请在这个网站上找到一款你感兴趣的无线耳机。"

**观察重点**:
- 如何开始搜索
- 使用什么导航方式
- 遇到什么困难
- 花费多长时间

**任务2: 了解产品**
"请查看这个无线耳机的详细信息。"

**观察重点**:
- 关注哪些信息
- 信息是否足够
- 有什么疑问
- 是否信任信息

**任务3: 购买决策**
"请将这个耳机加入购物车。"

**观察重点**:
- 如何找到加入购物车按钮
- 操作是否顺畅
- 有什么反馈
- 是否确认操作

**任务4: 购物车管理**
"请查看购物车，并将数量改为2个。"

**观察重点**:
- 如何找到购物车
- 如何修改数量
- 价格计算是否清晰
- 有什么困惑

**任务5: 结账流程**
"请尝试完成结账流程。"

**观察重点**:
- 流程是否清晰
- 表单是否易填写
- 有什么障碍
- 是否信任流程

#### 任务提示原则
- 先让用户自己尝试
- 如果卡住超过30秒，给予提示
- 提示从模糊到具体
- 记录所有提示点

### 阶段4: 深入访谈 (10分钟)
#### 思考性问题
1. **整体感受**: "整体来说，你对这个网站有什么感觉？"
2. **最喜欢什么**: "你最喜欢这个网站的哪个部分？为什么？"
3. **最困惑什么**: "有什么地方让你感到困惑或不确定？"
4. **改进建议**: "如果让你改进一个地方，你会改进哪里？"
5. **使用意愿**: "你会使用这个网站吗？为什么？"

#### 具体问题 (根据观察)
- "刚才你在[具体位置]犹豫了一下，当时在想什么？"
- "你期望[某个功能]应该怎样工作？"
- "这个设计和你平时用的有什么不同？"

### 阶段5: 结束和感谢 (5分钟)
#### 总结反馈
"感谢你完成所有任务，你的反馈非常宝贵。"

#### 后续说明
1. "测试数据将匿名处理，仅用于产品改进"
2. "如果有后续问题，可能会联系你"
3. "这是你的报酬/礼物，感谢你的时间"

#### 联系方式
"如果你后续有任何想法，可以通过这个方式联系我们。"

## 📈 测试指标计算

### 任务完成率
```
任务完成率 = (成功任务数 ÷ 总任务数) × 100%
```

### 平均任务时间
```
平均任务时间 = 总任务时间 ÷ 任务数量
```

### 错误率
```
错误率 = (错误次数 ÷ 总操作次数) × 100%
```
